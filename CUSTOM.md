## Конфигурация

`CUSTOM_UI` — JSON-объект, по умолчанию `{}`. Единственный пример включается строго boolean `true`: `{"hello":true}`. `false`, отсутствие флага или строка `"true"` не включают компонент. Некорректный JSON или значение другого типа дают `{}` и предупреждение без содержимого переменной. Для изменения окружения нужен recreate контейнера.

Поле доступно в публичном `/api/config`: никаких секретов в `CUSTOM_UI`. Отдельная русская локализация находится в `src/lib/custom/locales/ru-RU.json`. Собственные CSS-переменные не меняют базовые токены upstream.

## Как повторить переключение флага

Временный override вне `~/ai-dvokat` (например, `/tmp/custom-ui.yaml`):

```yaml
services:
  openwebui:
    environment:
      CUSTOM_UI: '{"hello":true}'
```

```sh
docker compose --env-file ~/ai-dvokat/.env -p legal-assistant \
  -f ~/ai-dvokat/deploy/compose.yaml -f /tmp/custom-ui.yaml \
  up -d --no-deps --pull never openwebui
```

Поменять `true` на `false`, повторить команду и обновить страницу. Вернуть стандартный запуск без override:

```sh
docker compose --env-file ~/ai-dvokat/.env -p legal-assistant \
  -f ~/ai-dvokat/deploy/compose.yaml up -d --no-deps --pull never openwebui
```

Файлы `~/ai-dvokat/deploy/openwebui.env` и `~/ai-dvokat/.env` не менялись. Bootstrap и регрессия из `owui/` не запускались: существующие модели, инструменты и данные сохранились. Первый пакет интерфейса не начинался.

### B2 — карточка результата, флаг выключен

`custom_ui.result_card === true` включает `custom/Result.svelte` только для завершённого сообщения модели `legal_workflows.*`. Точки подключения: импорт и обёртка штатного рендерера в `Messages/ContentRenderer.svelte`; одна строка proxy в `vite.config.ts` (`/legal-tools` → localhost:8000). Штатный рендерер сохранён в слоте — выключение флага возвращает исходный ответ.

Шесть разделов: Итог, Находки, Правки, Источники, Файлы, Расход и время. U1 читается из завершающего `<!-- legal-tools:job=<uuid> -->`; поддержан точный старый текст таймаута. Произвольные UUID из текста не используются. Если у сохранённого ответа маркера нет, карточка показывает его исходный текст и сохранённые источники без запроса задания; штатные файлы остаются под сообщением. Не выполняются поиск чужих заданий, запись в чаты или добавление маркеров задним числом.

API-клиент использует только same-origin путь, сессионный Bearer и запрет HTTP-redirect. Ошибки 401/403/сети/формата не скрывают исходный ответ и не выводят тело ответа сервера. Выполняющиеся задания опрашиваются с интервалом 3 секунды; переключение чата/флага отменяет запрос и таймер. Файлы скачиваются через авторизованную ручку по UUID, произвольный `download_url` из ответа не используется. Фрагмент источника — только сохранённый текст; это не B3 и не получение канонического receipt.

Контракт в `src/lib/custom/types.ts` привязан к прочитанным схемам от 02.11.2026, текущая версия — unversioned. Неизвестная будущая `schema_version` требует отдельного адаптера, вместо ошибочной интерпретации остаётся штатный ответ. До U5 отсутствующие находки, before/after/rationale и прочие поля отмечаются как непереданные, а не как успешно проверенные или пустые. Поддержка структурированных полей проверена синтетическими fixtures; их наличие в работающем продукте не заявляется.

Проверки подготовки: 16 тестов Playwright; 3 существующих Python-теста; TypeScript собственных модулей; svelte-check собственных компонентов — 0 ошибок и предупреждений. Дополнительно проверено подключение к полному dev-приложению: анонимный экран входа с флагом бренда on/off; выбор модели и черновик B1; карточка B2 в синтетическом сохранённом чате через подмену API только в тестовом браузере. Пользовательские данные не изменялись. Это не живая приёмка К+, загрузки файла, реального workflow и DOCX на новом образе.

### R4 — маркер задания не виден и не копируется

Задача — `~/ai-dvokat/docs/ui-task-r4-marker-2026-11-05.md`. Pipe дописывает последней строкой `<!-- legal-tools:job=<uuid> -->` (U1), Open WebUI 0.12.5 показывал его текстом под «Расход». Сохранённое сообщение реального разбора хранит текст и в `content`, и в `output` (один элемент `message` / `output_text`); рендерер берёт `output`, копирование — `getOutputText(output)`. Поэтому чистятся оба представления.

- `src/lib/custom/jobs.ts`: `stripJobMarker` удаляет ровно тот завершающий маркер, который распознаёт `jobIdFromMessage` (общее регулярное выражение), вместе с пробельными строками перед ним. Маркер посреди текста, без UUID, без `legal-tools:job=`, другие HTML-комментарии и UUID в тексте не трогаются; при двух маркерах удаляется только последний; пустая строка и не-строка возвращаются как есть. `stripJobMarkerFromOutput` делает то же для последнего непустого элемента `message` в `output`, в том числе если маркер разбит на несколько частей, не меняя исходный массив.
- Отрисовка: **существующая обёртка `CustomResult`** (`ContentRenderer.svelte`, та же строка `ai-dvokat:`) передаёт штатному рендереру `content` и `output` без маркера через параметры слота (`let:content let:output`). Выбрана она, а не новая строка: новых строк в upstream нет, очистка идёт при любых флагах (обе ветки `Result.svelte` отдают слот с очищенным текстом), а карточка B2 по-прежнему получает сырой `content` и находит задание по маркеру.
- Копирование, «Вставить в заметку» и озвучивание: `visibleResponseContent` в `ResponseMessage.svelte` проходит через `stripJobMarker` — одна точка `ai-dvokat:` (импорт и изменённая строка).
- Не меняются: сохранённое сообщение в базе, история для модели, режим редактирования (там сырой текст).
- **Экспорт:** стилизованный PDF (настройка по умолчанию) рисует те же компоненты сообщений — маркера нет. **TXT, простой PDF (`stylizedPdfExport=false`) и JSON берут сырой `content`/`output` — маркер там остаётся.** Правка потребовала бы новых точек в `layout/Navbar/Menu.svelte` и `layout/Sidebar/ChatMenu.svelte` (`getChatAsText`), по задаче не делалась. JSON — выгрузка данных, маркер в ней нужен так же, как в базе.

Тесты (`tests/custom/marker.spec.ts`, 9): функция на точном маркере, `\r\n`, двух маркерах, отсутствии маркера, не-строке и неточных форматах; `output` с разбитым маркером; **настоящий** `ContentRenderer` (обвязка `RendererHarness.svelte` с заглушками `$app/*`) при `result_card` false/true и для `content`/`output` — в DOM нет `legal-tools:job`, «Расход» на месте, карточка при включённом флаге запрашивает своё задание; маркер посреди текста и неточный маркер остаются; **настоящий** `ResponseMessage` — буфер обмена и «Вставить в заметку» без маркера. С откатом точек подключения 4 теста рендерера и 2 теста копирования падают, с правкой проходят. Всего 32 Playwright и 4 Python — успешно.
